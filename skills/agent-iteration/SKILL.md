# Agent 自我演进（技能发现 + 迭代护栏）

> 通用元技能（项目无关，任何工作区可用）。合并自 ai投研 项目的 skill-discovery 与 iteration-guardrails 实践，去项目化后独立存在。规则分两部分：**A. 找外部技能（吸收什么）**、**B. 迭代防漂移（怎么改自己）**。

## 本技能管什么（2026-09-14 由 description 移入：描述只留一句"何时用"）

**该用**：① 用户要找/评估外部 Agent 技能（"找找有没有 XX 类技能""这个技能值不值得装"）；② 技能/方法论迭代，或跨多轮长任务（>5 次工具往返），需要防止方向漂移与违背初心。

**不该用**：**仅因任务较长、或文中出现"技能/迭代/方法"等词就加载**。单轮工具调用、纯读写文件、纯事实检索等任务不需要本技能的评估流程与护栏。

**两部分做什么**：A = 吸收外部技能（质量四准则 + 落地四问 + 迭代闭环；具体搜索动作委托 `find-skills`）；B = 防方向漂移（初心锚点文件、每轮重读、3-Strike 升级、收尾对照）。

## 执行约束（最高优先，挂接 `AGENTS.md` 硬规则，本技能一切流程不得违反）

1. **范围/初衷以用户确认为准，禁止 Agent 自拟边界**：B1 锚点文件的"初衷 / 范围边界"必须是用户说过的话或用户确认过的表述；两者任一不明确时，按 `AGENTS.md` 硬规则「不确定→分三档处置」的**②档**处理——取最合理解释做到可验证、写明假设、一次交付由用户裁决，**不来回请示**；**不许用 Agent 推断替用户定义"要做什么/不做什么"**。
2. **安装/下载先列清单确认**：A 部分若落到实际安装（如 `npx skills add`），先列出拟安装每一项（名称/来源/大小量级/用途），用户确认范围后才执行；授权绝不扩大到清单外（挂接 `AGENTS.md`「安装/下载类授权」硬规则）。
3. **卡住先分性质，不要一律停下等**（对齐 `AGENTS.md` 硬规则「不确定→分三档处置」）：属**事实型**不确定（工具行为、环境、报错原因、文件内容）→ 查到证据再动，不反复请示；属**不可逆动作**（删除覆盖、安装、外部写入、发布）→ 停一次列清单等确认；属**意图/范围/授权边界**不清 → 按第 1 条②档处理。
4. **改动最小化 + 验证**：改动请求做最小安全范围修改并运行最近验证；只检查与报告的任务不得顺手改（挂接 `AGENTS.md`「权威与范围」）。

## A. 技能发现与吸收

> ⚠️ **搜索动作委托 find-skills（已全局加载）**——skills.sh leaderboard、`npx skills find` CLI 用法、安装命令等**不在此重写**，直接调 find-skills 技能执行。本部分只保留 find-skills 没有的：**质量验证 + 落地评估 + 迭代闭环**（即"搜到之后怎么办"）。若 find-skills 不可用（未加载），退回首段备注的简单搜索提示。

### A1. 快速搜索（委托 find-skills，此处仅备忘）

- 系统已装 `find-skills` → 按其 SKILL.md 执行（leaderboard → `npx skills find` → 呈现选项）。
- find-skills 不可用时兜底：skills.sh leaderboard + `npx skills find <关键词> --no-interactive` + web_search GitHub。

### A2. 质量验证四准则（机械执行，find-skills 只负责"找到"，不负责"验证"）

| 准则 | 门槛 | 说明 |
|---|---|---|
| 安装数 | 优先 1K+；<100 谨慎 | 生态内 battle-tested 信号 |
| 来源信誉 | 官方/知名组织优先 | 未知作者存疑 |
| GitHub stars | 源仓库 <100 star 存疑 | 与搜到的仓库交叉核对 |
| 新鲜度 | 最后更新 >12 个月 = 可能过时 | 迭代吸收时尤其重要 |

### A3. 落地评估四问（比通用门槛更关键——历史踩坑总结）

1. **方法论 vs 数据源分离？** 许多技能是"方法论可借鉴 + 数据源付费"（如 Octagon = 付费 MCP、LSEG = 企业订阅）。**方法论写进 references/，付费数据源只借鉴框架、不依赖其接口**；免费数据源才可做工具。
2. **当前项目适用性？** 披露框架（A 股预告/快报/正式 vs 美股 GAAP）、数据口径、领域节奏是否兼容；不兼容只吸收方法论层。
3. **归本项目哪个模块？** 新技能/方法放本项目技能包的正确子目录（单票分析 vs 组合层 vs 通用纪律），避免全堆一处。
4. **落地形式**：方法论 → `references/*.md`；可脚本化 → `tools/*.py`；规则修订 → 经用户批准 + 记 changelog，禁止自动改。

### A4. 迭代闭环

发现 → 评估（A3 四问）→ **向用户提议（含依据/预期效果）** → 用户批准 → 落地 → 记 changelog。评估过的技能记录留痕：SecondBrain 库内的**唯一留痕位是 `90 规则与状态/记忆台账.md`**（只增不改、只记结论＋决定性依据；**评估前先查该页**，命中同对象就复述已有结论再决定是否重评），本技能不另立记录位置，避免两处留痕。落地后回填『验证结果』用可观测判据：diff 变小／返工减少／澄清出现在实现之前；三者都没有就记『未验证』，不写感觉（2026-09-23 增）。

## B. 迭代护栏（防方向漂移/违背初心）

适用：技能/方法论迭代、跨多轮长任务（>5 次工具往返）、项目改造。**磁盘是持久锚，上下文是易失 RAM——一切重要的计划写盘。**

### B1. 开工前建初心锚点（非协商，必建）

当前项目根目录下 `_tasks/<任务名>.md`（若项目已有数据区约定则用之，如 ai投研 用 `research/_tasks/`）：

```markdown
# 任务：<短名>（YYYY-MM-DD 开工）
## 初衷（用户原话/需求要点，逐字保留，防措辞漂移）
<用户要什么、为什么>
## 范围边界（做什么 / 明确不做什么）
- 做：____
- 不做：____（超出即停，先问用户，不自动扩界）
## 验收标准（可对照检查）
- [ ] ____
## 涉及文件清单
## 阶段进度
| 阶段 | 状态 | 错误记录 |
## 收尾对照（实际改动 vs 初衷）
- 初衷内完成：____
- 初衷外新增（需说明为什么）：____
```

纪律：
- 每轮开工（尤其上下文压缩/恢复后）**先重读锚点文件**再动手；
- 每轮收尾更新阶段进度 + 错误记录；
- 多步计划写成「1. 步骤 → verify: 检查」格式，每步带可验证的完成判据，只列步骤不列验证＝不合格（2026-09-23 增）；
- **范围越界检查**：中途冒出的新需求若超出"不做什么"→ 停下列给用户决定，**不顺手扩界**（"顺手加需求"是漂移头号来源）；
- 收尾填"初衷外新增"栏——新增过多说明本轮换了任务，记入 changelog 提醒。

### B2. 3-Strike 协议（防"方向不对还硬干"）

同一目标动作失败后的升级路径，**绝不重复完全相同的失败动作**：

```
ATTEMPT 1：诊断 & 修 → 读错误、找根因、定向修
ATTEMPT 2：换路径 → 同一错误？换方法/换工具/换数据源（绝不原样重试）
ATTEMPT 3：重审假设 → 质疑前提、回初心文件看方向是否错了、更新计划
3 次失败后：升级用户 → 说明试了什么、具体错误、请用户定夺方向
```

### B3. 收尾记 changelog（版本史，只增不改）

每次修订记一行：`日期 | 改了什么 | 依据 | 预期效果 | 验证结果(回填)`——可回溯、可打包、修订效果可验证。

### B4. 与上下文压缩协同

跨多轮任务在压缩/新回合开始时：先读 `_tasks/` 锚点文件恢复方向（比任何人的记忆可靠）；锚点文件缺失且任务已过半 → 先补建再继续，禁止凭上下文印象硬推。

## 红线

- 不自动改方法论主文件：修订提议 → 用户批准 → 才改（防自我漂移）；
- 不重复同一失败动作（B2）；
- 不把"自我学习"当"联网更新行业数据"——数据更新是各项目 data 层的事，元技能学的是判断与流程偏差。

## 责任分工表（防各层重复/冲突，新方法论落地前先对照归属哪层）

| 层 | 载体 | 管什么 | 谁不能越界 |
|---|---|---|---|
| **① 行为硬规则（最高层）** | 壳级硬规则（如 `AGENTS.md`，旧名 `DSH.md`）、用户偏好与工作约束（SecondBrain 记忆层） | 追问/授权/凭据/沟通/最小改动/写回协议适用范围 | **一切技能、方法论不得违反①**；冲突时①优先 |
| **② 元任务纪律** | agent-iteration（本技能） | 跨多轮防漂移（B）+ 外部技能吸收评估（A） | 不重写①的硬规则；不替①定义授权边界 |
| **③ 领域方法论** | 各项目技能包（如 ai投研 / serenity-portfolio 的 SKILL.md + references） | 领域分析流程（投研预期差、选股组合、复盘校准） | 不新增跨项目通用纪律（那归②）；不违反①② |
| **④ 知识治理** | SecondBrain 记忆治理层（协议＋索引＋两本账；**文件清单以《可靠记忆索引》为准，本表不逐一列举**） | 知识库可信度分级、记忆晋升/降级、纠错账本、技能评估留痕 | 不接管③的方法论修订；candidate/验收状态由用户把关 |

**落地判断口诀**：内容同时可能归属多层时 → 取层号最小者管辖（① 最优先）；领域流程改进进③、通用纪律进②、记忆状态进④；**重复的判定标准 = 同一内容在两处都作为"权威定义"出现**（一处作为权威源、另一处只留指针 = 不算重复）。
